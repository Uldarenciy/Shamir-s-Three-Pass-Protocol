# Бесключевой протокол Шамира

Сначала инициатор передаёт собеседнику **сеансовый ключ K длиной 256 бит тремя проходами Шамира**, как в теории. Инициатором может быть Алиса или Боб. Затем участники шифруют этим ключом сообщения чата через **AES-256-GCM**. Писать можно в любой момент, без очереди.

Поддерживаются Linux и macOS, Python 3.10 или новее. Для AES используется готовая библиотека `cryptography`.

## Структура

```text
kr_proto/
├── alice/
│   ├── alice.py          # Действия Алисы
│   ├── protocol.py       # Вспомогательные функции Алисы
│   ├── alice.json        # Адрес Боба, порт, тайм-аут, каталог результатов
│   ├── parameters.json  # Общее простое число p
│   └── requirements.txt # Зависимость cryptography
├── bob/
│   ├── bob.py            # Действия Боба
│   ├── protocol.py       # Вспомогательные функции Боба
│   ├── bob.json          # Адрес прослушивания, порт, тайм-аут, каталог результатов
│   ├── parameters.json  # То же простое число p
│   └── requirements.txt # Та же зависимость
├── .gitignore           # Исключает секретные показатели, журналы и кэш из Git
└── README.md
```

Каждая папка самостоятельна: для запуска участника достаточно скопировать только его папку. Вспомогательные функции и открытый параметр p есть у обоих; секреты участники друг у друга не читают.

## Установка

В папке проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r alice/requirements.txt
```

Для двух участников на одном компьютере достаточно одного окружения. На другом компьютере установите зависимости из `requirements.txt` его участника.

## Запуск

Откройте два терминала в корневой папке проекта.

**Первый терминал — Боб:**

```sh
.venv/bin/python bob/bob.py
```

После строки «Ожидание Алисы» запустите **во втором терминале Алису:**

```sh
.venv/bin/python alice/alice.py
```

По умолчанию K создаёт Алиса. Чтобы **K создавал Боб**, запустите:

Первый терминал:

```sh
.venv/bin/python bob/bob.py --initiate
```

Второй терминал:

```sh
.venv/bin/python alice/alice.py --receive-key
```

`--initiate` — создать и передать K, `--receive-key` — принять его. Ровно одна сторона должна быть инициатором; при конфликте ролей программы завершаются с понятной ошибкой. Выбор зависит от флагов, а не от порядка запуска. TCP-сервером по-прежнему остаётся Боб, подключается Алиса.

После подключения выполняются три прохода Шамира. У каждой стороны сохраняется свой файл `.key` из **32 байт**, а в терминалах выводится его SHA-256 — отпечатки должны совпасть.

Затем появляется «Чат готов». **Первым может написать любой участник**, можно отправлять несколько фраз подряд и писать одновременно. Введите текст и нажмите Enter; собеседник увидит восстановленную фразу. Боб остаётся сервером, ожидающим подключения Алисы: это роль соединения, а не очередь в чате.

Шамир используется один раз для передачи K. Каждая дальнейшая фраза шифруется AES-256-GCM с этим K. Открытый текст в сеть не отправляется. К сообщению добавляются nonce и тег целостности; повреждённое сообщение не принимается. Для nonce используются разные обозначения направлений и счётчики, поэтому они не повторяются в одной сессии. Реализация AES взята из [официальной библиотеки cryptography](https://cryptography.io/en/latest/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM).

Лимит одной фразы — **64 КиБ UTF-8**, число фраз не ограничено. Старого ограничения 200 байт нет: текст больше не превращается в число для Шамира. Для завершения введите **`/exit`** — команда тоже передаётся в зашифрованном виде. EOF завершает чат аналогично. Принудительная остановка — `Ctrl+C`.

При входящем сообщении приглашение `Вы:` печатается заново. Если вы в этот момент набирали фразу, её ввод сохраняется, но вывод терминала может визуально смешаться с сообщением.

## Настройки и результаты

На одном компьютере менять настройки не нужно. Для разных компьютеров в `alice/alice.json` замените `host` на адрес компьютера Боба. В `bob/bob.json` значение `0.0.0.0` означает ожидание на всех сетевых интерфейсах. Порт должен совпадать у сторон; по умолчанию **5050**. Файлы `parameters.json` тоже должны совпадать: в них исходное 2048-битное простое p из RFC 3526, группа 14.

`timeout` ограничивает время подключения Алисы и ожидание сообщений Шамира при передаче K. В чате тайм-аут отключён, чтобы можно было спокойно набирать текст. Боб ждёт первого подключения до `Ctrl+C`. `directory: "data"` задаёт папку результатов внутри папки соответствующего участника.

После запуска появляются `alice/data/` и `bob/data/`. Каждый запуск получает новые имена файлов:

- `private_*.json` — собственные секретные показатели: `a, d_A` у Алисы, `b, d_B` у Боба;
- `key_*.key` — сеансовый K, ровно 32 байта;
- `exchange_*.jsonl` — время, направление и полное содержимое передаваемых сообщений.

В журнале `OUT` — попытка отправки, записанная до передачи; `IN` — приём; `IN_PARTIAL` — оборванный или слишком длинный приём. Первые две записи — отправка и приём открытого обозначения роли (`INITIATE` или `RECEIVE`). Следующие три записи относятся к трём проходам Шамира с K. Далее каждая фраза и `/exit` передаются одним сообщением: в журнале записан полный nonce и шифртекст с тегом в hex-виде. На отправку у одной стороны есть соответствующий приём у другой. Данные журналов сторон при успешном обмене совпадают. При сетевой ошибке доставку проверяют по журналу получателя. У файлов одного запуска совпадает идентификатор в имени.

## Краткая теория для защиты

**Бесключевой протокол Шамира** позволяет передать сообщение без предварительного обмена общим секретным ключом.

Участники:
- **Алиса** — по умолчанию отправитель сеансового ключа K.
- **Боб** — по умолчанию получатель K; флаги позволяют поменять роли. Затем оба равноправно отправляют фразы.
- **m** — числовое представление сеансового ключа K, не текста чата.
- **p** — общее открытое простое число, `1 ≤ m < p`.

### 1. Выбор секретных показателей

Алиса выбирает секретное число $a$, взаимно простое с $p-1$:

$$
\gcd(a,p-1)=1
$$

Затем вычисляет обратный показатель $d_A$:

$$
a\cdot d_A\equiv1\pmod{p-1}
$$

Боб аналогично выбирает $b$ и вычисляет $d_B$:

$$
\gcd(b,p-1)=1
$$

$$
b\cdot d_B\equiv1\pmod{p-1}
$$

Все четыре показателя остаются секретными.

### 2. Четыре шага протокола

**Шаг 1. Алиса → Боб**

Алиса шифрует сообщение своим показателем $a$:

$$
x_1=m^a\bmod p
$$

**Шаг 2. Боб → Алиса**

Боб дополнительно шифрует полученное число своим показателем $b$:

$$
x_2=x_1^b\bmod p=m^{ab}\bmod p
$$

**Шаг 3. Алиса → Боб**

Алиса снимает своё шифрование с помощью $d_A$:

$$
x_3=x_2^{d_A}\bmod p
$$

Поскольку $a\cdot d_A\equiv1\pmod{p-1}$:

$$
x_3=m^{abd_A}\bmod p=m^b\bmod p
$$

**Шаг 4. Боб (локально)**

Боб снимает своё шифрование с помощью $d_B$:

$$
x_3^{d_B}\bmod p=m^{bd_B}\bmod p=m
$$

Таким образом, Боб восстанавливает исходное сообщение.

### 3. Почему протокол работает

По **малой теореме Ферма** для простого $p$ и $1\le m<p$:

$$
m^{p-1}\equiv1\pmod p
$$

Из условия для Алисы:

$$
a\cdot d_A\equiv1\pmod{p-1}
$$

Следовательно, существует целое число $k$:

$$
a\cdot d_A=1+k(p-1)
$$

Тогда:

$$
m^{ad_A}=m^{1+k(p-1)}
$$

$$
=m\cdot(m^{p-1})^k\equiv m\pmod p
$$

Аналогично для Боба:

$$
m^{bd_B}\equiv m\pmod p
$$

**Главная идея:** при последовательном возведении в степень показатели перемножаются. Поскольку умножение коммутативно, Алиса может снять своё шифрование после добавления шифрования Боба, а затем Боб снимает своё.

### 4. Числовой пример

Исходные данные:

| Параметр | Значение |
|---|---|
| Простое число $p$ | 23 |
| Сообщение $m$ | 10 |
| Показатель Алисы $a$ | 5 |
| Обратный показатель $d_A$ | 9 |
| Показатель Боба $b$ | 7 |
| Обратный показатель $d_B$ | 19 |

**Проверяем обратные показатели:**

$$
5\cdot9\bmod22=1
$$

$$
7\cdot19\bmod22=1
$$

**Выполняем протокол:**

| Шаг | Вычисление | Результат |
|---|---|---|
| 1. Алиса → Боб | $10^5\bmod23$ | 19 |
| 2. Боб → Алиса | $19^7\bmod23$ | 15 |
| 3. Алиса → Боб | $15^9\bmod23$ | 14 |
| 4. Боб локально | $14^{19}\bmod23$ | 10 |

**Результат:** Боб восстановил исходное сообщение $m=10$.

### 5. Реализация в Python

Возведение в степень по модулю:

```python
x1 = pow(m, a, p)
```

Вычисление обратных показателей:

```python
d_A = pow(a, -1, p - 1)
d_B = pow(b, -1, p - 1)
```

Обратные показатели существуют благодаря условию взаимной простоты. Их также можно найти **расширенным алгоритмом Евклида**.

> **Важно:** пример с `p = 23` предназначен только для обучения. В классическом виде протокол не обеспечивает аутентификацию участников и уязвим к атаке «человек посередине» (MITM).

Пример для доски: `p=23`, `m=10`, у Алисы `a=5, d_A=9`, у Боба `b=7, d_B=19`. Тогда `x1=19`, `x2=15`, `x3=14`, восстановленное `m=10`.

Инициатор создаёт `K = secrets.token_bytes(32)`. Чтобы передать любые 32 байта, в том числе ведущие нули, используется `m = int.from_bytes(K, 'big') + 1`. После трёх проходов получатель получает m и восстанавливает `K = (m - 1).to_bytes(32, 'big')`. Единица исключает нулевое m; длина ключа как битовой строки всегда 256 бит. Обозначение K в диаграмме из учебника соответствует передаваемому здесь значению m.

Выше формулы даны для инициатора Алисы. Если K создаёт Боб, в формулах меняются местами `a, d_A` и `b, d_B`. Секретные a,b,d_A,d_B используются только для передачи K. Дальше `AESGCM(K)` шифрует и расшифровывает чат. При каждом запуске создаются новые показатели и новый K.

Секретные пары `a, d_A` и `b, d_B` создаются у каждого участника независимо, сохраняются в `private_*.json` и не передаются по сети. Заранее общего секретного ключа нет. Это не разделение секрета Шамира с долями и полиномом. Классическая схема не аутентифицирует участников и не защищает от активного посредника.

Для понимания кода начните с `main()` в `alice.py` и `bob.py`; затем откройте `chat()` в `protocol.py` — в ней находятся три прохода и восстановление текста.
