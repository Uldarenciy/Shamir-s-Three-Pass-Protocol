# Бесключевой протокол Шамира

Алиса передаёт Бобу случайный **256-битный ключ за три сообщения**. Нужен только Python 3.10 или новее; дополнительные пакеты не требуются.

## Структура

```text
kr_proto/
├── alice/
│   ├── alice.py          # Действия Алисы
│   ├── protocol.py       # Вспомогательные функции Алисы
│   ├── alice.json        # Адрес Боба, порт, тайм-аут, каталог результатов
│   └── parameters.json  # Общее простое число p
├── bob/
│   ├── bob.py            # Действия Боба
│   ├── protocol.py       # Вспомогательные функции Боба
│   ├── bob.json          # Адрес прослушивания, порт, тайм-аут, каталог результатов
│   └── parameters.json  # То же простое число p
└── README.md
```

Каждая папка самостоятельна: для запуска участника достаточно скопировать только его папку. Вспомогательные функции и открытый параметр p есть у обоих; секреты участники друг у друга не читают.

## Запуск

Откройте два терминала в корневой папке проекта.

**Первый терминал — Боб:**

```sh
python3 bob/bob.py
```

После строки «Ожидание Алисы» запустите **во втором терминале Алису:**

```sh
python3 alice/alice.py
```

Обе программы покажут три сообщения, путь к своему ключу и его **SHA-256**. Отпечатки должны совпасть. Сам ключ находится в файле `.key` и занимает ровно **32 байта = 256 бит**. Для нового обмена повторите команды. Остановить ожидание можно через `Ctrl+C`.

Можно запускать и из папки участника: `python3 bob.py` или `python3 alice.py`. Настройки находятся относительно программы, поэтому текущая папка терминала не влияет на их поиск.

## Настройки и результаты

На одном компьютере менять настройки не нужно. Для разных компьютеров в `alice/alice.json` замените `host` на адрес компьютера Боба. В `bob/bob.json` значение `0.0.0.0` означает ожидание на всех сетевых интерфейсах. Порт должен совпадать у сторон; по умолчанию **5050**. Файлы `parameters.json` тоже должны совпадать: в них исходное 2048-битное простое p из RFC 3526, группа 14.

`timeout` задаёт время без новых данных после подключения. Боб ждёт первого подключения до `Ctrl+C`. `directory: "data"` задаёт папку результатов внутри папки соответствующего участника.

После запуска появляются `alice/data/` и `bob/data/`. Каждый запуск получает новые имена файлов:

- `private_*.json` — собственные секретные показатели c и d;
- `key_*.key` — ключ из 32 байт, сохраняется при успешном завершении стороны;
- `exchange_*.jsonl` — время, направление и полное содержимое сообщений.

В журнале `OUT` — попытка отправки, записанная до передачи; `IN` — приём; `IN_PARTIAL` — оборванный или слишком длинный приём. При успешном обмене у каждой стороны три записи с одинаковыми данными. При сетевой ошибке доставку проверяют по журналу получателя. У файлов одного запуска совпадает идентификатор в имени.

## Краткая теория для защиты

Бесключевой означает, что заранее общий **секретный** ключ не нужен. Собственные секретные показатели у сторон есть. Алиса и Боб независимо выбирают c, взаимно простое с p−1, и вычисляют d:

```text
gcd(c, p−1) = 1
c · d ≡ 1 (mod p−1)

Алиса → Боб: x1 = m^c_A mod p
Боб → Алиса: x2 = x1^c_B mod p
Алиса → Боб: x3 = x2^d_A mod p
Боб локально: m = x3^d_B mod p
```

В Python вычисление степени по модулю — `pow(m, c, p)`, обратного показателя — `pow(c, -1, p-1)`. Обратный показатель существует благодаря условию взаимной простоты; его можно найти расширенным алгоритмом Евклида.

Почему работает: для простого p и ненулевого m малая теорема Ферма даёт `m^(p−1) ≡ 1 mod p`. Поэтому `m^(c·d) ≡ m mod p`. Умножение показателей коммутативно: Алиса снимает своё преобразование после добавления преобразования Боба, затем Боб снимает своё локально.

Пример для доски: `p=23`, `m=10`, у Алисы `c=5, d=9`, у Боба `c=7, d=19`. Тогда `x1=19`, `x2=15`, `x3=14`, восстановленное `m=10`.

В программе Алиса создаёт `secrets.token_bytes(32)` и переводит ключ в `m = int.from_bytes(key, 'big') + 1`, чтобы исключить ноль. Боб восстанавливает `(m-1).to_bytes(32, 'big')`, сохраняя ведущие нулевые байты. SHA-256 нужен только для сравнения результатов в терминалах.

Ключ выбирает Алиса: это передача ключа, а не совместный выбор. Это также не разделение секрета Шамира с долями и полиномом. Классическая схема не аутентифицирует участников и не защищает от активного посредника. Длина ключа 256 бит не означает такую же криптостойкость всей схемы. Четвёртого сообщения с подтверждением нет: при показе сравните результаты обеих сторон.

Для понимания кода начните с `main()` в `alice.py` и `bob.py`; затем посмотрите вспомогательные функции в `protocol.py`.
